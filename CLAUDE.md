# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это

Одностраничный лендинг веб-разработчика на фрилансе (Mr. Web, Роман Баукин).
Статика без сборки: `index.html` — единственная страница, стили лежат внутри
в `<style>`, **JavaScript на странице нет вообще**. Зависимостей, `package.json`
и тестового раннера нет.

Контент на русском. Коммиты в этом репозитории тоже пишутся по-русски.

## Команды

Сборки, линтера и тестов нет — их отсутствие намеренное.

```bash
start index.html                 # посмотреть локально (Windows)
git push origin main             # это и есть деплой: Pages пересобирается сам
gh api repos/RomanBaukin/mr-web-landing/pages --jq '.status'          # building | built
gh api repos/RomanBaukin/mr-web-landing/pages/builds/latest --jq '.commit'
```

Живой адрес: https://romanbaukin.github.io/mr-web-landing/

## Ограничения хостинга

Сейчас GitHub Pages (project page, то есть **подпуть** `/mr-web-landing/`),
позже переезд на Netlify (корень домена). Отсюда жёсткие правила:

- **Все пути относительные.** `assets/logo.svg`, никогда `/assets/logo.svg`.
  Абсолютный путь сломается как минимум на одном из двух хостингов.
- **Абсолютные URL живут ровно в двух местах:** блок в `<head>` файла
  `index.html` (`canonical`, `og:url`, `og:image` и те же адреса внутри
  JSON-LD) и ссылки на главную в `404.html`. При смене домена правятся
  только они. В `index.html` есть комментарий-маркер над этим блоком.
- В `404.html` ссылка на главную **намеренно** абсолютная: Pages отдаёт этот
  файл по любому несуществующему пути, и относительный адрес считался бы от
  него, а не от корня сайта.
- `_headers` и `_redirects` — для Netlify, Pages их игнорирует. Лежат заранее.
- `.nojekyll` обязателен, иначе Pages прогоняет сайт через Jekyll.
- Внешних запросов быть не должно ни одного: шрифты самохостятся в
  `assets/fonts/` (Geologica и Golos Text, переменные, только кириллица и
  латиница — четыре файла на весь диапазон весов).

## Сквозной мотив: семь дней

Страница продаёт зафиксированный срок, и это её единственный визуальный
приём. Мотив недели повторяется в четырёх местах, поэтому правка в одном
требует взгляда на остальные:

1. шкала в первом экране (`.scale` / `.track` / `.seg`);
2. раздел «Как проходит неделя» (`#process`, те же пять этапов подробно);
3. прайс — у каждой услуги полоса `.price-bar`, ширина задаётся инлайновым
   `--w` и пропорциональна сроку;
4. кейсы — факт срока набран отметкой (`.case-fact`).

Порядок секций: `.hero` → `.scale` → `.terms` → `#work` → `#process` →
`#services` → `#pricing` → `#guarantees` → `#about` → `#faq` → `#contact`.
У первых трёх нет `id`, они адресуются классом. Доказательство стоит раньше
цены, гарантии сразу после неё.

## Токены и правила оформления

Всё оформление идёт от `:root` (`--paper`, `--paper-2`, `--ink`, `--muted`,
`--rule`, `--mark`, `--mark-deep`), ритм — от `--step: 28px`, поля — от
`--edge`. Типографика: `--display` (Geologica) на заголовки, `--text`
(Golos Text) на текст.

- `--mark` — единственный акцент. Залитая кнопка на странице одна (`.cta`),
  вторичные действия текстовые, чтобы не спорить с ней по весу.
- Единственный залитый блок — финал (`.close`, на `--ink`).
- Не возвращать: капслочные надписи над секциями, метастроки через `·`,
  нумерацию там, где нет настоящей последовательности (`01/02/03` отданы
  дням в `#process`, у услуг их нет намеренно).

## Контраст — жёсткое ограничение, а не пожелание

`--mark` на `--paper` даёт **4,91:1** при норме 4,5. Запаса практически нет,
и это ломает решения, которые в другом проекте прошли бы незаметно:

- Любое **осветление** красного роняет подпись ниже нормы: белый на 8% →
  4,41, на 15% → 3,97, на 30% → 3,04. Поэтому блик на кнопке сделан тёмной
  волной, а не светлой (на пике 6,6:1).
- Прозрачность вместо иерархии не работает: подпись на красном на 75%
  непрозрачности давала 3,29. Иерархия внутри залитых блоков держится
  **кеглем**, а не прозрачностью.
- Кнопка на тёмном финале даёт к фону 2,93 при норме 3,0 для границы
  компонента — поэтому там у `.cta` есть светлый кант.

**Любая правка `--mark`, `--paper`, `--ink` или наложений на кнопки требует
пересчёта.** Считать формулой WCAG, а не на глаз.

## Анимации

Движения на странице ровно два, оба один раз описаны в CSS и оба обёрнуты
в `@media (prefers-reduced-motion: no-preference)`.

**Шкала.** Вид этапа задан четырьмя переменными на `.seg` — `--bg`,
`--edge-c`, `--c-day`, `--c-name`. Они наследуются внутрь, поэтому одна
анимация на сегменте перекрашивает и фон, и обе подписи; отдельные анимации
детям не нужны. Тайминг: `--t` и `--start` на `.track`, индекс этапа —
инлайновый `--i` в разметке. Режим заполнения здесь несёт смысл: горящие
этапы идут с `animation-fill-mode: none` (значение по умолчанию) и гаснут
сами, а `.seg-last`, наоборот, гасится через `backwards` на `4 × --t` и
после этого возвращается к своему постоянному красному.

**Блик на кнопках** (`.cta::after`) стартует на 8,2 с — после того, как
отыграет шкала, чтобы два движения не спорили. Направление слева направо,
то же, что у шкалы.

Две ловушки, на которые уже наступали:

- **Не анимировать свойства раскладки** (`left`, `width`, `top`). Прошлая
  версия бегунка анимировала `left`, и композитор оставлял красный след в
  стартовой позиции. Только `transform` и цвет.
- `@media (max-width: 720px)` переводит шкалу в столбец: рамка переезжает с
  `border-left` на `border-top`, но цвет обеих берётся из `--edge-c`, иначе
  анимация перестаёт её перекрашивать.

## Ловушка с пропорциями картинок

У `<img>` с атрибутами `width`/`height` presentational-высота выигрывает у
`aspect-ratio`, пока не задан `height: auto`. Без него ширина и высота обе
оказываются определёнными и пропорция молча игнорируется — кейсы
рендерились вертикальными, а раздел занимал вдвое больше места. Правило
касается `.case-shot` и `.about-photo`.

## Что в репозитории ещё не настоящее

- `assets/case-1.svg`, `assets/case-2.svg`, `assets/roman.svg` — заглушки.
- Названия и описания проектов в `#work` придуманы. **Раздел в текущем виде

  убрать раздел целиком.
- `Mr-Web-landing-standalone.html` — прежняя версия дизайна (бандл на 1,5 МБ),
  лежит только для отката. Не редактировать.

## Проверка изменений

Тестового раннера нет, но «на глаз» здесь недостаточно — все ошибки этого
проекта находились измерением. Готовых скриптов в репозитории нет, они
собираются под задачу на `puppeteer-core` с локальным Chrome
(`C:/Program Files (x86)/Google/Chrome/Application/chrome.exe`).

Что проверять после правок вёрстки:

- `document.documentElement.scrollWidth` против `clientWidth` на 1440 / 1280
  / 768 / 390 — горизонтального переполнения быть не должно;
- список запросов страницы: внешних ноль, путей с ведущим `/` ноль;
- `document.fonts` — все четыре загружены, заголовок реально набран
  Geologica, а не запасным системным;
- иерархия заголовков: один `h1`, без пропусков уровня;
- первый `Tab` попадает на `.skip` и она становится видимой;
- под `prefers-reduced-motion: reduce` — `document.getAnimations().length === 0`
  и залит сразу день 7;
- анимации проверяются выставлением `animation.currentTime` в конкретные
  моменты, а не ожиданием таймеров: так результат воспроизводим.

**Headless Chrome через `--window-size` не даёт окно уже ~500px** и молча
обрезает снимок. Для мобильных ширин использовать эмуляцию устройства
через puppeteer, иначе получите ложное «переполнение».
